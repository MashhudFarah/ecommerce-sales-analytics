## Cleaning

Payment methods and countries come in with different cases and spacing —
`Net Banking` / `NetBanking` / `net banking`, `USA` / `U.S.A` / `United States`.
I normalise both.

The bigger decision was order status. I split it into fulfilled and
cancelled/returned, which is why the numbers here look smaller than they could
have.

## What went wrong

**Cancelled and returned orders were counted as revenue.** My first total was
about 8% too high and nothing looked broken. Fixed by splitting order status
before any sum.

**A missing price silently became 0.** Pandas filled the gap and average order
value dropped for no visible reason. Now I check for nulls first.

**The ad-spend file didn't line up with the orders.** Some ROAS values came out
below 1.0. The date ranges were off. Fixed by joining on month.

## Limits

- The Streamlit app isn't deployed, it runs locally only
- Basic KPIs: revenue, spend, ROAS, AOV, order count. No forecasting or cohorts
  (those are in the SQL companion)
- Sample data, so the absolute figures mean nothing. The method is the point
- The Excel dashboard is static — change the source and re-run `build_dashboard.py`

## Definitions

- **Gross revenue** — all orders including cancelled and returned. $1.39M
- **Fulfilled revenue** — `order_status = 'Delivered'` only. $767K
- **Lost revenue** — cancelled and returned. $252K
- **ROAS** — fulfilled revenue ÷ ad spend, so cancellations don't inflate it.
  767K / 375K = ~2.04x
- **Revenue after ad spend** — fulfilled revenue − ad spend. ~$392K. This is
  **not profit** — no cost of goods, shipping or platform fees

Cancelled and returned orders count in gross revenue but are excluded from
fulfilled revenue, ROAS and any repeat-purchase metrics.
